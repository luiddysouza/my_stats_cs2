## Story

**As a** usuário do app,
**I want** buscar um jogador de CS2 pelo Steam ID ou URL do perfil e ver as últimas 10 partidas dele,
**so that** eu possa avaliar rapidamente a performance recente do jogador sem precisar sair do app.

## Acceptance Criteria

1. *(AC-01 / FR-01)* Quando o usuário informa um Steam ID válido (17 dígitos, começa com `765`) e busca, o app carrega o perfil do jogador e navega para a tela de lista de partidas
2. *(AC-02 / FR-01)* Quando o usuário informa uma URL de perfil Steam válida (`steamcommunity.com/profiles/xxx` ou `steamcommunity.com/id/xxx`) e busca, o app carrega o perfil e navega para a lista de partidas
3. *(AC-03 / FR-01)* Quando o usuário informa um texto que não é nem Steam ID nem URL válida, o app exibe uma mensagem de erro adequada inline (sem navegar)
4. *(AC-04 / FR-02)* Após uma busca bem-sucedida, a tela de lista exibe até 10 partidas carregadas do mock
5. *(AC-05 / FR-02)* Se nenhuma partida for encontrada para o jogador, a tela exibe um estado vazio explícito com mensagem
6. *(AC-06 / FR-03)* Cada item da lista exibe: mapa, data, resultado (W/L/D como badge colorido), kills, assists, deaths e rating do jogador pesquisado

## Dev Notes

### Padrão Repository + UseCase (tech preset Flutter)
```
UseCases só conhecem as interfaces (domain/repositories/).
Implementações mock ficam em data/repositories/.
Providers instanciam o UseCase injetando o repositório mock:

final searchPlayerUseCaseProvider = Provider((ref) {
  return SearchPlayerUseCase(MockPlayerRepository());
});
```

### fpdart Either
```dart
// Retorno de sucesso
return Right(player);

// Retorno de falha
return Left(InvalidInputFailure(message: 'Texto inválido'));

// Consumo no Notifier
final result = await _useCase(input);
result.fold(
  (failure) => state = AsyncData(SearchState(errorMessage: failure.message)),
  (player) => state = AsyncData(SearchState(player: player)),
);
```

### Validação de Steam ID (AC-01)
```
SteamID64: exatamente 17 dígitos numéricos, começa com "765"
Regex: r'^765\d{14}$'
```

### Validação de Steam URL (AC-02)
```
Aceitar:
  steamcommunity.com/profiles/76561198XXXXXXXXX
  steamcommunity.com/id/<customUrl>
Regex (profiles): r'steamcommunity\.com/profiles/(\d{17})'
Regex (custom):   r'steamcommunity\.com/id/([^/\s]+)'
```

### Estado de loading no botão (UX)
> Substituir o botão por `CircularProgressIndicator` durante a busca, não desabilitar — evita layout shift.

### Passar dados entre rotas (go_router)
> Usar `context.go('/matches', extra: player.steamId)` — o router já está configurado para receber `extra` na rota `/matches`. Para passar `displayName` também, considere passar um `Map<String, String>` como extra.

### Buscar stats do jogador no MatchCard
> `MockData.matchStats` é uma `List<PlayerMatchStatsEntity>`. Filtrar por `stats.where((s) => s.player.steamId == searchedPlayer.steamId && matches no match)`. Como o mock não tem matchId em `PlayerMatchStatsEntity`, mapear por índice: `MockData.matchStats[index]` onde index corresponde à partida.

### ProviderScope (verificação)
> Confirmar em `lib/app.dart` que `ProviderScope` está FORA do `MaterialApp.router` (wrapping), não dentro. Caso contrário, providers não funcionarão corretamente em widgets abaixo do root.
